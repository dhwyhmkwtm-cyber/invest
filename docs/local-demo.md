# 自宅で試す (AWS・ドメイン・クレジットカード不要)

本番と同じプログラムを、自宅のパソコンか iPad のブラウザで動かして、操作と動きを確かめる方法です。
**メールは外に一切送られず**、ツールの中の「テスト受信箱」に届きます。

| 確かめられること | 確かめられないこと (本物の AWS が必要) |
|---|---|
| 宛先リストの取り込み・重複統合・お断り表示や取得元なしの除外 | 実際に相手の受信箱に届くか (迷惑メール扱いされないか) |
| キャンペーン作成・A/B 2パターン・キュー・1社1通・1日上限・ウォームアップ | SPF / DKIM / DMARC の設定が正しいか |
| メール本文と法定表示 (送信者・住所・電話・配信停止URL) | Gmail・Outlook 側の表示 |
| 配信停止 (本文リンク・メールソフトのボタン) → 抑止リストに即反映 | |
| バウンス・迷惑メール報告 → 抑止リスト・自動停止 | |
| レポート・ダッシュボード・管理者への通知メール | |

中身は本番と同じ構成です (PHP 8.3 + Apache + MySQL 8.0 + 1分ごとの cron)。違いは「SES に送る代わりにテスト受信箱へ入れる」部分だけです。

---

## 方法A: パソコン (Windows / Mac) — おすすめ

### 1. Docker Desktop を入れる (初回だけ)

1. https://www.docker.com/products/docker-desktop/ からダウンロードしてインストール
2. Docker Desktop を起動し、画面左下が緑 (Engine running) になるまで待つ

### 2. プログラムをダウンロード

1. GitHub でこのリポジトリを開く
2. 左上のブランチ切り替えで `claude/mailer-phase2` を選ぶ
3. 緑の「Code」ボタン → 「Download ZIP」→ 解凍する

### 3. 起動

- **Windows**: 解凍したフォルダを開き、アドレスバーに `powershell` と入力して Enter
- **Mac**: 「ターミナル」を開き、`cd ` (最後に空白) と入力してから解凍したフォルダをドラッグ&ドロップして Enter

次のコマンドを入力して Enter:

```
docker compose up --build
```

初回は5分ほどかかります。`[mailer] ready:` と表示されたら準備完了です。

### 4. 使う

ブラウザで **http://localhost:8080/admin/** を開き、ユーザー名 `admin`、パスワード `demo-pass-2026` でログインします。

止めるときは、コマンドの画面で `Ctrl + C`。次回は同じコマンドで、前回のデータのまま起動します。
データを消して最初からやり直すときは `docker compose down -v`。

## 方法B: iPad だけで (GitHub Codespaces)

インストール不要で、ブラウザの中にパソコンを借りて動かします。個人の GitHub アカウントには毎月の無料枠があります (2コアのマシンなら月60時間程度)。

1. Safari で GitHub のこのリポジトリを開き、ブランチを `claude/mailer-phase2` にする
2. 緑の「Code」ボタン → 「Codespaces」タブ → 「Create codespace on claude/mailer-phase2」
3. 画面が開いたら、そのまま3〜5分待つ (自動で起動します)
4. 下の「ポート」タブで `8080 配信ツール` の地球儀アイコンを押す → 開いたページの末尾に `/admin/` を付けて開く
5. `admin` / `demo-pass-2026` でログイン

使い終わったら、github.com の「Codespaces」一覧から停止してください (無料枠の消費が止まります)。

> 方法B は GitHub の環境で動くため、こちらでは事前に動作確認できていません。うまく開かない場合は方法A をお使いください。

## 試してみる手順 (15分)

1. **宛先リスト** → 「CSV / Excel 取り込み」で、ダウンロードしたフォルダ内の `demo/sample-list.csv` を選んで取り込む
   - 14行中: 新規12件・統合1件 (同じアドレスの大文字違い)・書式不正1件・取得元なし1件・お断り表示1件 と表示される
2. 同じ画面の「未確認分をチェック」を押す
3. **キャンペーン** → 「デモ: 石綿廃棄物用袋のご案内」→ 「キューに追加」→ 「配信開始」
   - 9社分がキューに入る (同じ会社の2アドレスは窓口の info@ だけ。お断り・取得元なしは入らない)
4. **テスト受信箱** → 「cron を今すぐ1回実行」を2回押す (放っておいても1分ごとに自動で動きます)
   - 9通届き、パターンA・Bが交互に使われている
   - `bounce@simulator.amazonses.com` はバウンス、`complaint@simulator.amazonses.com` は迷惑メール報告として処理される
5. 1通開いて、本文末尾の法定表示を確認し、ボタンで「クリックした」「メールソフトの配信停止ボタンを押した」を試す
6. 別の1通で、本文の配信停止URLを開き「配信を停止する」を押す
7. **抑止リスト**: 配信停止2件・バウンス1件・迷惑メール報告1件・お断り表示1件が入っている
8. **キャンペーン** でもう一度「キューに追加」→ 停止した宛先は二度と入らない (0件)
9. **レポート**・**ダッシュボード** で数字を確認する

自分で作った CSV (自社収集のアドレスの一部など) を取り込んでも大丈夫です。メールは外に出ません。
ただしドメインの存在確認 (MXチェック) は本物の DNS に問い合わせます。
