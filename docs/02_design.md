# 02. 最小構成の設計（Step 2）

## 1. 採用する最小構成

```
[Siri] 「配達メッセージ」
   │
   ▼
[ショートカット「配達メッセージ」]  ←─ 読み込み ── [ファイルアプリ] このiPhone内/配達メッセージ/messages.json
   │  ① データ読み込み  ② 音声入力  ③ 正規化  ④ 検索  ⑤ 表示  ⑥ コピー/終了
   ▼
[クリップボード]（「コピーする」を選んだときだけ・本文のみ）
```

| 構成要素 | 採用 | 理由 |
|---|---|---|
| 起動 | Siri + ショートカット名「配達メッセージ」 | 仕様どおり。追加設定不要 |
| 音声入力 | 「入力を要求」（テキスト） | Siri 実行時は音声、画面実行時はキーボード（音声入力ボタンも使える）の両方に対応できる。「テキストを音声入力」は Siri 実行中の挙動が不安定とされるため、予備案とする |
| データ | JSON 1ファイル（`data/messages.json`） | 仕様の第一候補。Codex で生成・検証でき、第2段階の書き戻し・バックアップにそのまま使える |
| 保存場所 | **このiPhone内**/配達メッセージ/messages.json | オフライン動作を最優先（第2段階の「iPhone本体の独立した保存データを優先」と整合）。iCloud Drive への保存は第2段階のバックアップで扱う |
| 正規化表 | ショートカット内の「テキスト」に `shortcut/normalize_map.json` を貼り付け | 全角数字・漢数字の変換表を1か所で管理。参照実装と同じファイルを使う |
| 表示＋選択 | 「メニューから選択」の見出しに番号・キーワード・本文を表示 | 表示と「コピーする/終了する」を1画面で完結できる |
| 検証 | 参照実装 `tools/haitatsu.py`（Python・標準ライブラリのみ） | ショートカットと同じ手順をPC上で再現し、データとテストケースを事前検証する |

## 2. データ構造（schemaVersion 1）

```json
{
  "schemaVersion": 1,
  "revision": 1,
  "updatedAt": "2026-10-27T09:00:00+09:00",
  "messages": [
    {
      "id": "msg-0001",
      "number": 1,
      "keyword": "到着",
      "aliases": ["とうちゃく", "着きました"],
      "text": "お待たせいたしました。…",
      "category": "到着連絡",
      "createdAt": "2026-10-27T09:00:00+09:00",
      "updatedAt": "2026-10-27T09:00:00+09:00",
      "deletedAt": null
    }
  ]
}
```

| 項目 | 型 | ルール（`haitatsu.py validate` で検査） |
|---|---|---|
| schemaVersion | 整数 | 現在は `1`。構造を変えたら上げる |
| revision | 整数 ≥1 | データを更新するたびに +1（第2段階の「古いデータによる上書き防止」に使う） |
| updatedAt | ISO 8601 | データ全体の最終更新日時 |
| id | 文字列 | 一意・変更しない |
| number | 整数 ≥1 | 未削除データ内で一意（重複はエラー） |
| keyword / aliases | 文字列 / 文字列配列 | `\|` 不可、keyword は `.` 不可（候補辞書のキーに使うため）、全角数字不可、前後の句読点不可、番号と区別できない語（`3`, `三番` など）不可。キーの重複は**警告**（検索時に候補提示） |
| text | 文字列 | 改行は `\n`。絵文字・記号はそのまま保持 |
| category | 文字列 | 分類（MVPでは表示・検索に未使用） |
| deletedAt | null / ISO 8601 | null 以外は通常検索から除外 |

JSON Schema は `data/messages.schema.json`。

## 3. 検索仕様（ショートカットと参照実装で共通）

### 3.1 入力の正規化

| 手順 | 処理 | 例 |
|---|---|---|
| N1 | 空白（全角空白・改行含む）をすべて除去 `\s+` → 空 | `置き 配` → `置き配` |
| N2 | 小文字化 | `ABC` → `abc` |
| N3 | 全角数字 → 半角（正規化表 `fullwidth`） | `３番` → `3番` |
| N4 | 前後の句読点を除去 `^[。、．.,，!！?？]+\|[。、．.,，!！?？]+$` | `到着。` → `到着`（Siri が句点を付ける対策） |
| N5 | 番号判定: `^(?:番号)?([0-9〇零一二三四五六七八九十]+)(?:番目\|番\|ばんめ\|ばん)?$` に一致したら番号として扱う。漢数字は正規化表 `kanji` で変換し、`十` は下記規則で処理。先頭の0を除去 | `三番`→3 / `十二`→12 / `二十`→20 / `03`→3 |

`十` の処理（この順に適用）: `^([0-9])十([0-9])$`→`$1$2`（二十三→23）、`^十([0-9])$`→`1$1`（十二→12）、`^十$`→`10`、`(?<=^[0-9])十$`→`0`（二十→20）。結果が数字だけにならなければ番号扱いしない（`十十` など）。百以上の漢数字は対象外。

> 漢数字の変換は**入力全体が番号の形のときだけ**行う。キーワード中の漢字（例「一階」）は変換されない。

### 3.2 照合

1. 入力が空 → 「聞き取れませんでした」を表示して終了。
2. 削除済み（`deletedAt` が null 以外）は対象外。
3. **番号の場合**: `number` の完全一致のみ。部分一致は行わない。
4. **キーワードの場合**: 各定型文について照合文 `|keyword|alias1|alias2|`（N1・N2を適用）を作り、`|入力|` を含むかで**完全一致**を判定。
5. 完全一致が0件で、入力が2文字以上 → 照合文が入力を含むもの（**部分一致**）を候補として集める。

### 3.3 結果の扱い

| 結果 | 動作 |
|---|---|
| 完全一致 1件 | そのまま表示 |
| 完全一致 複数件 | 「リストから選択」で候補提示（`【番号】キーワード`） |
| 部分一致（1件でも） | 候補提示。**自動選択しない**（仕様「曖昧な一致で誤った文章を自動選択しない」） |
| 0件 | 「該当する定型文がありません:「入力」」を表示して終了 |

> **仕様解釈（要確認）**: 部分一致による候補提示は仕様に明記がないため追加提案として実装している。不要であればショートカットの手順 E-7〜E-9 を省略すれば完全一致のみになる（`docs/05_open_issues.md` 参照）。

### 3.4 表示とコピー

- 表示: `【番号】キーワード` + 区切り線 + 本文（`haitatsu.py` の `format_display` と同じ）。
- 選択肢: 「コピーする」「終了する」。
- 「コピーする」: 本文（`text`）だけを「クリップボードにコピー」。完了通知を表示。
- 「終了する」: 何もせず終了（クリップボード不変）。
- 他アプリへの自動入力・送信は行わない。

## 4. エラー処理

| 状況 | 検出方法 | 表示 |
|---|---|---|
| データファイルがない／読めない | 「入力から辞書を取得」の結果に値がない | 「データを読み込めません。ファイルアプリの配達メッセージ/messages.json を確認してください」 |
| schemaVersion が 1 以外 | 値の比較 | 「データの形式が対応していません（schemaVersion）」 |
| 入力が空 | 正規化後の値がない | 「聞き取れませんでした。もう一度お試しください」 |
| 該当なし | 一致・候補とも0件 | 「該当する定型文がありません:「入力」」 |
| 候補選択でキャンセル | 「リストから選択」のキャンセル | ショートカット終了（クリップボード不変） |
