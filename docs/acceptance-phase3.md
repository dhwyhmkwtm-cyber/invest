# フェーズ3 受け入れ確認

受け入れ基準: **法定表示のないテンプレートは保存できない。閾値超過で翌日の上限が上がらない。**

## 自動テスト

```sh
php app/tests/run.php Phase3
```

| 基準 | テスト |
|---|---|
| 法定表示は外せない | 「【受け入れ基準】法定表示はテンプレートから外せない」— 本文に住所や配信停止を書かなくても、テキスト・HTMLの両方に送信者名・住所・電話・問い合わせ先・配信停止URLが必ず入る (法定表示はテンプレートに保存せず送信時に付けるため、外す方法がない) |
| 閾値超過で上限が上がらない | 「【受け入れ基準】閾値超過で翌日の上限が上がらない / 2日続いたら停止」— 本来500件に上がる日に、前日のバウンス率が2%だと200件のまま。2日続くとキャンペーン停止+管理者通知 |
| (関連) 計画どおりの引き上げ | 「初日は200件、3営業日問題なければ500件に上がる」。土日祝は判定しない。送信が上限の半分未満の日は日数に数えない |
| (関連) A/B の自動決定 | 各パターン規定数で決定し、未送信キューを勝ちパターンに付け替える。段階3に入ったら件数不足でも決定 |

## テスト環境での確認

テスト環境で計画どおり何日も送るのは現実的でないため、計画を短くして確認する (確認が終わったら元に戻す):

```php
'warmup' => ['plan' => [[1, 5], [1, 10], [0, 20]], 'max_bounce_rate' => 0.02, 'max_complaint_rate' => 0.001],
```

- [ ] 1日目は5件で止まる
- [ ] 翌営業日に管理画面「ウォームアップ」の記録に「継続」「引き上げ」が出て、上限が10件になる
- [ ] 前日の送信先に `bounce@simulator.amazonses.com` を混ぜてバウンス率を上げると、翌日「据え置き」になり上限が上がらない
- [ ] パターンA・Bを登録すると交互に送られ、段階3に入ると「A/Bテスト: 決定済み」になり、管理者にメールが届く
