# フェーズ2 受け入れ確認手順

受け入れ基準: **社内アドレス50件への送信で、二重送信ゼロ、配信停止が即時反映、バウンス・苦情のテスト通知が抑止リストに入る**

## A. 自動テスト (開発環境)

```sh
php app/tests/run.php
```

`Phase2AcceptanceTest` の各テストが受け入れ基準に対応する。

| 基準 | テスト |
|---|---|
| 50件送信で二重送信ゼロ | 「50件送信: 全員に1通ずつ・二重送信ゼロ」「途中で落ちた送信中の行は再送せず…」「通信タイムアウト…」 |
| 配信停止が即時反映 | 「配信停止 (ワンクリック/リンク) は即時反映され、以後送られない」 |
| バウンス・苦情が抑止リストに入る | 「永久バウンス・苦情のSES通知が抑止リストに入る」 |
| (関連) 法令上の送信条件 | 「取得元なし・お断り表示・MX不良・書式不正の宛先には送らない」「1社につき1通」 |
| (関連) 速度制御・自動停止 | 「1日上限・時間帯の外では送らない」「苦情率が0.1%を超えたら自動停止…」 |

## B. 本番環境での確認 (社内50件)

1. 社内アドレス48件 + SES のメールボックスシミュレーター2件を CSV にする

   ```csv
   会社名,メールアドレス,担当者名,業種,地域,URL,取得元,取得日
   社内テスト01,taro@example.co.jp,山田,テスト,東京都,https://t01.test.invalid,社内名簿,2026-11-01
   社内テスト02,hanako@example.co.jp,佐藤,テスト,東京都,https://t02.test.invalid,社内名簿,2026-11-01
   ...
   バウンス試験,bounce@simulator.amazonses.com,,テスト,東京都,https://t49.test.invalid,SESシミュレーター,2026-11-01
   苦情試験,complaint@simulator.amazonses.com,,テスト,東京都,https://t50.test.invalid,SESシミュレーター,2026-11-01
   ```

   ※ ツールは「1社1通」で、会社は URL 列のドメイン (無ければメールのドメイン) で区別する。
   社内アドレスは全部同じドメインなので、**URL 列に1行ずつ違うダミーURLを入れる** (入れないと50件が1社にまとめられ、1通しか送られない)。
   ※ 同じドメイン宛てが続くと、ワーカーは2秒ずつ間隔をあける。cron 1回で十数件ずつ進む。

2. 管理画面で取り込み → MXチェック → キャンペーン作成 (1日上限 50) → テンプレート登録 → キューに追加 → 配信開始
3. cron を数回動かす (待つか、SSH で `php bin/cron.php` を手動実行)

### チェック項目

- [ ] 「キュー確認」で送信済 50 件、失敗・結果不明 0 件
- [ ] 各受信箱に **ちょうど1通** 届いている (cron を手動で何度実行しても増えない)
- [ ] 本文末尾に送信者名・住所・電話・問い合わせ先・配信停止URLが表示されている
- [ ] 1人が本文の配信停止リンクから停止 → 「抑止リスト」に即座に表示される
- [ ] 1人が Gmail の「配信停止」ボタン (ワンクリック) で停止 → 即座に抑止リストに表示される
- [ ] 停止した人を新しいキャンペーンでキューに追加しようとしても対象に入らない
- [ ] `bounce@simulator.amazonses.com` が 理由「永久バウンス」で抑止リストに入る
- [ ] `complaint@simulator.amazonses.com` が 理由「迷惑メール報告」で抑止リストに入る
- [ ] 「レポート」に送信・到達・バウンス・苦情・配信停止が記録されている
- [ ] 管理者宛てに日次レポートが届く

> 50件中バウンス1件・苦情1件は自動停止の母数 (既定100件) 未満なので停止しない。自動停止の動作確認をしたい場合は、テスト中だけ `guard.min_sample` を 10 に下げる。
